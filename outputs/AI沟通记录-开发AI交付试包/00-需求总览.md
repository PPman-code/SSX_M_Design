# AI 沟通记录 · 开发 AI 交付试包

设计来源为 SSX_M_Design `3e3a909`。本次为 D 类交付试验。正式学员和意向客户使用同一套沟通接入规则，按两个宿主页面各自出包。录音和整理共用一个页面。三个独立任务弹窗分别出包，其余简单确认跟随各自父流程，已有筛选继续复用，表单字段选择器随表单。

意向客户和正式学员的入口包提供独立最终样式 CSS、Vue 2 / SCSS 接入说明、390px 状态图、路由交接、合成验收数据及接口待确认项。入口包使用已解析的浅色色值，便于旧项目接入。

## 发给开发

拿任一 ZIP 交给能读写目标仓库的 AI，告诉它「读取包内 README，在当前仓库按包内规则和验收用例实现」。如工具无法直接读 ZIP，先解压成目录。每包带单独接入契约和验收用例。多个开发并行时，以此总览对齐记录标识和状态交接。

## 包和联调顺序

1. [意向客户详情](01-意向客户详情接入.zip)或[正式学员详情](09-正式学员详情接入.zip) → [开始 AI 记录说明](06-开始AI记录说明弹窗.zip) → [录音与整理进度](02-AI录音与整理进度页.zip)（含 [结束录音确认](07-结束录音确认弹窗.zip)）。
2. 人员页待处理入口 → [待处理列表](03-待处理AI记录列表.zip) → 整理进度或 [AI 原始详情](04-AI原始记录详情页.zip)（含 [编辑标题与说话人](08-编辑AI记录标题与说话人弹窗.zip)）。
3. 原始记录就绪 → [沟通记录表单](05-沟通记录表单页.zip) → 提交成功进入已保存表单；后续修改保存回人员沟通页。手动新建直接进同一表单。

## 联调约定

- 人员 ID 稳定标识当前关联学员；AI 原始记录 ID 标识录音、转写及总结；正式记录 ID 标识提交后的沟通记录。AI 来源由入口决定，三类 ID 的实际字段与转换规则由开发服务对齐。
- 记录状态为录音中、暂停、中断、转写中、总结中、失败、无有效内容、就绪。已提交由正式记录关联单独表示，失败附阶段。目标服务负责设备会话约束、失败重试、提交幂等、访问权限和删除权限。
- 录音、播放器、AI 内容、权限、持久化与附件进度在原型为演示。实际麦克风、长时/锁屏/断网录音、后台任务、上传、服务端鉴权及真实模型结果需独立联调。下次跟进类型必填标识与原型校验存在差异，需按实际业务配置确认。PC 展示单独对接。
- 试包截图来自桌面 Chrome 手机仿真。开发侧仓库和微信真机待验收。
