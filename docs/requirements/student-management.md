V/I/B/D，沿用当前 codex/prospective-students 分支开发。首版草稿展示 1.0，不代表已上线；日常调整不新增版本。

## 依据及范围

Figma：https://www.figma.com/design/hoN0voWKmRtnWBPuzMw1yB/?node-id=4300-74914 。2026-10-20 重新读取设计上下文和截图。页面布局、五张示例卡片的姓名/状态/金额/数量/有效期以该稿为准。使用项目语义主题色，不引入第三方 UI 或图标库。

首页「学员管理」进入 /pages/students/v1；工作区可用 ?page=students 直达，右侧配置跟随当前页面，无新增业务配置项。独立打开和手机预览不画顶部返回/标题导航；工作区保留模拟微信外壳。向上滚动时搜索/排序/筛选工具栏随内容滑走，只有分类页签吸顶；向下回到顶部后恢复工具栏。

实现：搜索学员/手机号，全部/待沟通/欠费/生日页签（含数量和方向键导航），姓名及余额/数量/录入时间排序，右侧筛选草稿/确认/重置，五类状态卡片，负余额和数量警示，号码旁电话、二维码/课程/详情入口。电话图形 14px，头像 42px、6px 圆角，卡片 8px 圆角；独立操作目标保留至少 44px。数据区保留四列，不搬用意向客户的三列跟进卡片。

七个 SVG 均从参考稿下载到 public/pages/students/v1，按原始宽高使用。微信外壳复用本地 MobilePage 已有素材。

## 模拟与真实业务边界

本仓库尚无学员管理需求 PRD 或生产接口契约。本次以 Figma 列表为设计样本；排序、状态/余额/有效期筛选为本地演示，不作为现有业务规则的确认结果。示例数据固定为稿中的五名学员及旧日期，不按当前时间自动改写设计稿。

待沟通、欠费和生日使用独立示例标记（各两名），其最终定义和计数由真实系统提供。欠费不简单等同于剩余学费为负；不根据示例数据推导真实财务规则。

搜索和筛选先作用于示例数据，各页签计数基于这些结果；页签再选择其子集。排序重复点击同项切换方向。筛选取消/遮罩/关闭丢弃草稿，重置待确定生效；不同字段取交集、状态内取并集。默认保留 Figma 五卡顺序。用户确认两页数量栏统一 40px；分类页签的选中文字使用 color.text.brand，下划线使用同色阶 color.background.brand.bold，深浅色随项目 token 切换。

真实二维码、课程和详情业务没有在本次重新设计，入口当前提示待对接，不显示虚假业务成功。拨号使用示例号码的 tel: 链接；脱敏场景无 tel: 链接，不能用本地查询参数替代服务端权限。

仅用于检查的直达参数：state=loading/empty/error/forbidden；phone=masked。刷新恢复示例数据，无持久化、不连接生产 API。
