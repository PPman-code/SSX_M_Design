适用于学员管理、意向客户管理及后续同类人员列表。2026-10-20 根据两个本地设计草稿归纳；初始审查为 D 文档变更；后续仅迁移下文用户明确确认的尺寸，其他候选项保持待迁移。

## 保留业务差异

- 客户三列跟进摘要与学员四列财务/有效期摘要分别由业务决定；标签顺序、数字格式、负值提示、列数和数值层级不为外观一致强行合并。
- 客户批量选择、添加客户、性别与跟进信息，学员分类 Tab、二维码与课程入口各有用途。公共组合提供可选槽位，不制造另一页没有的功能。
- 客户当前搜索栏吸顶，学员仅 Tab 吸顶。滚动差异是现状；未获交互变更授权时不互相套用。
- 状态文字必须说明含义，同一语义使用同类 token；“试听”和“体验课报名”等不能仅凭名称接近就合并业务状态。

## 图标与组件收敛

1. 先查本地 Icon 名称和现有调用点。图标图形尺寸与按钮命中区域分别记录；不能把所有图标直接放大到热区尺寸。
2. 当前 Figma 原始 SVG 是已有来源例外，并不表示页面可继续任意复制图标。迁移前记录原稿节点、资源路径、缺失的 ssx-design 对应项；保留原形，不能换近似图形冒充完成。
3. 单色图标最终应通过公共入口跟随语义颜色；不把整页 `img` 反色当成通用主题方案。彩色图形、头像和品牌资产单独处理。
4. MobilePage、SideDrawer、SheetChoiceGroup、SheetActions 继续按注册 API 使用。Search 搜索框已有稳定 API，由两页消费；身份区、状态标签和列表状态仍是候选抽象；先定义两个消费者都适用的 API，再决定是否注册 Recommended，禁止提前制造全能人员卡片。
5. 默认值变化先检索所有调用方。临时页面覆盖要记录原因、适用范围及退出条件；不得用更高优先级 CSS 掩盖公共规范冲突。

## 审查与验收

新建或统一同类列表时，对照两个样本检查：搜索几何 → 数量条 → 卡片与身份信息 → 状态标签 → 图标 → 筛选草稿/排序反馈 → 空/加载/失败/无权限 → 底部安全区。视觉任务不改变业务回调、字段、排序规则或滚动策略。

布局或交互迁移验证 360/375/390/430px、Light/Dark、独立路由与微信模拟视口，检查长姓名、长数字、清除搜索、触控重叠、键盘焦点及关闭回焦；运行项目规定的 check/build/e2e。真机键盘、实际拨号和生产权限验收单独记录。

现状与未完成迁移见 [2026-10-20 审查清单](../docs/audits/2026-10-20-list-pages/README.md)。规范更新不等于清单问题已修复。
