# 移动端页面模式

组件示例 /mobile，工作区 /，交付 /handoff（均为 HashRouter 路由）。业务页 /pages/<page-name>/<version>，由 src/page-registry.ts 登记。
工作区与交付使用同一导航外壳；左侧切换栏目只更新主内容区，并标记当前栏目。/handoff 保留可直接打开与刷新的地址，切回预览保留本次会话的画布宽度设置，不再显示独立的交付页导航。

## 顶部层级、滚动与底部工具栏（已确认）

来源：用户于 2026-10-21 明确确认，并要求后续开发页面遵循。这里的“在顶部”首先表示初始布局位置，不等于各栏都设置 sticky/fixed。先确定层级高度，再单独确定滚动行为。

| 层级 / 区域 | 常见用途 | 总高度 |
| --- | --- | --- |
| 顶部第一层 | 主导航、搜索栏，或没有上方业务导航内容的独立 Tab | 56 CSS px |
| 顶部第二层 | 上方已有一层业务导航/搜索内容时的分类 Tab、次级导航 | 48 CSS px |
| 列表第三层 | 数量、批量管理等列表摘要/操作栏 | 40 CSS px |
| 底部工具栏 | 添加、保存、确认等标准单行操作 | 56 CSS px，底部安全区另加 |

- Tab 按所在层级定高：独立作为第一层时 56px；上方已有第一层时 48px，不能一律固定成 48px。
- 典型结构是“第一层搜索 56px + 第二层 Tab 48px + 数量/批量操作 40px”。第三层通常随列表滚动，不默认理解成第三条导航或第三条吸顶栏。不要求每个页面凑齐三层；没有 Tab 时，数量/批量操作栏仍按其 40px 列表操作角色处理。
- 常见上滑行为：第一层随内容被推走，只保留第二层吸顶于应用滚动视口顶部；继续保留 48px，不因它滚到最上面而重新变成 56px。不能因两栏初始都位于顶部，就默认让两栏一起吸顶。返回页面顶部时按正常文档流恢复排列。
- 只有一条顶部业务栏时，使用第一层 56px；是否吸顶按页面已确认的滚动要求决定。已有页面的明确规则优先，不在文档升级时自动改写交互。
- 微信模拟顶部栏、手机系统状态栏、桌面工作区工具栏属于外部容器，不计入业务页面的 56/48/40 层级，也不在独立打开时重复绘制。
- 高度包含本栏内边距、边框及分隔线；安全区和模拟 Home 区在底部工具栏 56px 之外计算。按钮仍遵循公共 Button 40px 视觉高度，上下各 8px；40px 热区不能撑高或跨栏抢占相邻操作。已有明确的多行操作区自然增高规则继续保留，不把多行内容压进 56px。
- 这是页面组合层级规则，不全局修改表单 Input、Picker、Dialog、弹层选项行或组件示例的尺寸。Search 当前默认 56px 对应第一层；其他层级需要搜索组合时按已确认层级设计适配，不假定组件已经提供尚不存在的尺寸 API。

## 页面类型与现有工作区

列表：标题与搜索/筛选 → 主要列表 → 加载更多/结束反馈。每行主信息优先，辅助信息换行；不缩小 PC 表格冒充移动布局。
表单：顶部返回与标题 → 标签置顶的字段组 → 保存区。说明必填、即时/提交校验、失败恢复和未保存离开行为。
详情：状态与主信息 → 分组内容 → 主操作。底部固定区预留安全区和内容避让。
选择器：短列表用底部弹层，长列表加搜索或独立页，区分即时选择与确认提交。
排序弹层（学员管理、意向客户共用同一几何，样式集中在 styles/product.css，暂不抽组件）：标题统一「排序方式」；每行左侧标签 + 方向箭头（紧贴文字 4px，仅选中行显示），行尾对勾仅选中行显示；行高 48px（用户 2026-10-21 确认，取代此前两页沿用的 54px），字号 regular，选中行文字 brand-accessible；底部固定提示「再次点击已选项切换升序 / 降序」（caption 字号）。选中后即时关闭并给出轻提示「已按降序排列 / 已按升序排列」（两页一致，学员页 2026-10-21 补齐）。新页面排序沿用 .student-sort-options / .prospect-sort-options 同款结构，不另起样式。
全页面依场景覆盖正常、加载、空、错误重试、无权限和禁用状态。
PC 工作区与手机产品页分离；手机直接打开业务页面路由，不显示桌面设备边框。?chrome=wechat 仅用于设计对照，模拟系统栏与微信导航；真实页面使用 safe-area，不重复绘制系统组件。

工作区左侧放导航，深浅色切换位于侧栏底部；中间卡片工具栏左侧放通用预览设置（画布宽度），右侧放页面打开入口，下方为预览画布；右侧「页面配置」随预览中实际打开的业务页面切换。页面专属状态按组折叠，常用组默认展开，后续页面的模拟配置统一加在右侧，不放在产品页或设备下方。组件预览无业务配置时隐藏右侧面板。重复设计规范通过 /handoff 查阅，Figma 来源与独立打开保留在预览工具栏。窄屏工作区的页面配置显示在预览上方。

首页 /pages/home/v1，工作区 ?page=home；报表中心「出勤率」进入 /pages/attendance/v1?from=home；「我的」页不再提供重复入口。返回保留 theme/role/chrome；示例数据与模拟身份不代表后端接入。

工作区左侧仅保留「组件预览」「设计规范与交付」「项目预览」三个 Tab，不列业务页面标题、数量与逐页入口。项目预览默认进入首页，产品页面通过内部入口与底部导航访问；旧 ?page=my/attendance 的直接预览地址继续可用，并统一高亮项目预览。

微信容器外壳只用于项目 iframe 预览（chrome=wechat），顶部为关闭/标题/域名/更多，底部浏览历史按实际应用路由启用。手机链接不带 chrome 参数，页面不绘制容器导航；document.title 提供页面标题。

模拟微信栏左上角关闭图标仅作外观展示，点击实际返回应用内上一页；无上一页时回到首页，保留身份/主题/外壳参数，不关闭项目预览。

右侧配置以同源 iframe 报告的实际路由为准，不固定为工作区最初选择的页面。首页进入出勤率报表、上课明细或切换到「我的」时，同步页面名称、版本与现有展示配置；返回时同步恢复。嵌套页面的配置变更只替换当前预览的展示参数，保留前进/后退历史。预览位置与配置消息校验来源窗口和 origin；仍属于设计模拟，不连接真实接口。

工作区固定使用手机外壳与对应的模拟栏，不提供「手机外壳 / 无外壳」和「微信外观预览」切换控件。手机预览与独立打开的链接继续不带模拟栏参数。

模拟 Home 指示条本身没有独立底色：无微信浏览历史栏时透明叠加在产品底部，底部导航的背景延伸到屏幕边缘；无底部导航时延续内容背景并保留底部内容避让。有历史栏时，Home 区域随微信历史栏背景。仅影响桌面模拟外壳，不改变真实页面安全区。

人员管理列表跨页面审查按 [list-pages.md](list-pages.md) 执行。数量条、身份信息及工具栏先对照两个样本；搜索框、卡片等共同几何仍有待迁移项，不将当前差异视为业务要求。

### 页面背景覆盖检查（2026-10-23）

MobilePage 通用 .product-page 当前默认使用 my.canvas；业务页指定背景时使用 .product-page.<场景类>，避免同优先级受 CSS 加载顺序覆盖。要求连续底色的 Tab、底栏需对照浏览器最终计算色，而不只检查声明使用了语义变量；吸顶状态另核对 surface。客户详情已迁移并增加明暗主题计算色回归，其余页面不据此声称已完成迁移。
